# Performance & FX overhaul (branch perf/gpu-fx, 2026-09-28/29)

Goal: room for crazy boss fights full of special effects and many more
destructible physics objects. Every change was measured before/after
(interleaved A/B against a frozen server of the previous state) and every
simulation change is proven behaviour-identical where it claims to be.

## Where the time went (before)

Profiled at 196af51 (RTX PRO 3000 laptop, headless Edge, 1280x720):

- The cell sim was cheap in normal play (0.3-1.3 ms/tick) but the boss-fight
  and flood scenes were **sim-bound**: 29-39 fps and 23-28 fps. The top cost
  was not material rules but the ActivityGrid's per-swap halo bookkeeping
  (~23% of CPU), the electrical tracker, and RNG boxing.
- Rendering spent most of `compose` drawing every sprite, creature and
  particle pixel by pixel on the CPU into a float buffer that was then
  dirty-tracked, converted to half floats and uploaded as one bounding
  rectangle (often the whole 1280x720 frame, ~7 MB).
- Physics was capped at 80 bodies / 2800 terrain colliders; Rapier 0.19
  never let a heap fall asleep, so every body was simulated forever.

## What changed

| Area | Change | Proof |
|---|---|---|
| Sim | ActivityGrid: halos dilated once per step with word-parallel bit ops (sim halo 1 cell, render halo 2); tighter reclassify loop; flag planes for airborne water and the charge set; baked cell predicates | `tests/sim-golden-large.test.ts` (new multi-chunk golden: state, colours, draw counts, activity planes identical) |
| Sim | RNG stream state in an Int32Array (no heap-number boxing per draw under pointer compression) | every golden unchanged |
| Render | GPU particles: particles as points in a GPU FX layer, light-sampled in the vertex shader | `probe-gpu-fx.mjs` |
| Render | GPU overlay: every sprite pixel write is an ordered command scattered on the GPU (premultiplied rgb + coverage) instead of the staged CPU upload | `probe-gpu-fx.mjs STRICT=1`: 0-3 px = noise floor |
| Render | Light propagation in WASM SIMD (AssemblyScript), bit-identical, 2.5x | `tests/wasm-light.test.ts` |
| Render | Resting rigid bodies replay their recorded Pen art (bit-identical) | `probe-gpu-fx.mjs` art-cache check |
| Physics | Rapier 0.19 -> 0.21, SIMD build (lazy, scalar fallback), `lengthUnit` 10, voxel terrain chunks, body cap 80 -> 400 | `probe-physics-stress.mjs`, `bench-rapier-terrain.mjs`, all tests |
| FX | GPU sparks (`ctx.sparks`): 65k-slot GPU sim, bounces off the cave, drawn in the FX layer; explosions and lightning use it | `probe-gpu-sparks.mjs` |
| Tooling | `perf-fx-suite.mjs`, `bench-sim.mjs`, `bench-light.mjs`; `perf-particles-12k.mjs` fixed (it measured ~5 particles) | |

Runtime A/B flags: `postFx.gpuOverlay`, `postFx.gpuParticles` (both default
on). Probe seams: `window.__bodyArtCache = false`.

Physics alone (vs the branch just before the Rapier upgrade): -40% (80
bodies), -37% (400-body pile); the 400-body stress probe runs at 1.9-2.2 ms
per tick with no solver faults (800 bodies also fault-free).

4x CPU throttle (a crude phone proxy — DevTools throttling distorts render
costs): quiet 12.8 -> 16.7 fps, boss 3.3 -> 4.5 fps (frame -26% / -27%).
Real phones still need real testing.

## Using GPU sparks (boss fights)

```ts
ctx.sparks?.burst(x, y, {
  count: 400,            // sparks in this burst
  speed: 3,              // cells/tick; each spark gets 35%-125% of it
  kind: 'spark',         // 'spark' additive, bounces | 'ember' opaque, rises, flickers
                         // | 'smoke' lit by the light field, blended | 'magic' additive twinkle
  colors: [0xffd27a, 0xff8030],
  glow: 1.3,             // brightness (self-lit kinds)
  angle: -Math.PI / 2,   // cone centre (default up)
  spread: Math.PI,       // cone half-angle (default all round)
  life: 40,              // ticks (+-30%; default per kind)
  radius: 4,             // spawn disc
});
```

Sparks are cosmetic: they read the grid (bounce off solids, hiss out in
liquid) and never write it. Up to 16,384 queued per frame and 65,536 alive;
a storm of ~50,000 spawned per second holds 120 fps on the dev laptop. With
no GPU compose (CPU/WebGPU frames) a thinned set becomes ordinary cosmetic
particles.

## Known limits and follow-ups

- **Overload policy.** The fixed-step clock catches up with up to 4 ticks per
  frame, so an overloaded tick shows as a low frame rate at correct game
  speed. A brief slow-motion under extreme load (Noita's choice) would keep
  the frame rate up; that is a feel decision, not made here.
- **Balls in heaps.** Rapier sleeps islands by velocity; a ball wedged in a
  heap keeps a residual contact velocity (~3 cells/s at zero displacement) and
  can hold its island awake. Forcing sleep made heaps explode; bleeding the
  velocity did not stick. Boxes (crates, planks, kegs) sleep.
- **Death beat.** Bodies now sleep, so the death ragdoll "settles" sooner and
  the game-over overlay can arrive earlier.
- **Ragdoll substeps.** The world still steps 6x while the death ragdoll is
  awake: Rapier 0.35's per-island substeps tear the ragdoll's joints on a hard
  landing (tests/player-ragdoll.test.ts).
- `verify-barrels.mjs`' cluster check fails identically on main (stale probe
  geometry, pre-existing).
- The WebGPU backend still uses the staged overlay path.
